# Field profiles — what a 200L Computer Engineering intern plausibly does

Use these to draft logbook days and report sections when the student's own evidence does not
cover them. Pick the profile closest to the student's company field and role. Blend two when
the company straddles fields. Keep every item generic: no invented names, numbers or paperwork.

---

## A. IT support, networking and infrastructure
*(retail, offices, schools, banks' branches)*

**Tasks:** onboarding and asset tagging of PCs; preventive maintenance (cleaning, thermal paste
check, disk health check, Windows updates); printer and spooler faults; crimping and testing
RJ45/CAT6 cable; labelling patch panels; switch port and VLAN checks; Wi-Fi coverage checks;
DHCP/static IP record updates; backup router failover tests; VPN client setup; user account
creation and password resets; CCTV/DVR checks; UPS battery tests; helpdesk ticket logging and
closure; documenting a network layout.

**Tools:** crimper, cable tester, multimeter, Windows Device Manager, `ipconfig`, `ping`,
`tracert`, `nslookup`, Advanced IP Scanner, router/switch admin page, Active Directory or local
user manager, ticketing sheet.

**Illustrations:** LAN topology diagram, cable run layout, troubleshooting flowchart (no connectivity),
UPS load/backup-time bar chart.

**Theory links:** binary/IP numbering, OSI model layers, circuit basics (cabling and power),
routing fundamentals, Boolean logic.

---

## B. Software and web development
*(software house, fintech, agency, in-house dev team)*

**Tasks:** environment setup (Git, editor, runtimes); reading an existing codebase; fixing small
bugs from an issue tracker; writing a small feature or script; writing unit tests; code review as
an observer then as a reviewer; API testing with Postman or curl; database queries and schema
reading; writing documentation; deployment shadowing; standup and sprint meetings.

**Tools:** Git/GitHub, VS Code, Python/JavaScript/Java (as the company uses), Postman, SQL client,
browser DevTools, Linux terminal, issue tracker (Jira, Trello or similar).

**Illustrations:** system architecture block diagram, request/response sequence diagram, flowchart
of a feature's logic, simple bar chart of test pass rate (only if real).

**Theory links:** programming fundamentals (OOP, control flow), data structures, discrete maths
and Boolean logic, intro to databases, engineering communication.

---

## C. AI, data and machine learning
*(data teams, AI start-ups)*

**Tasks:** data cleaning and labelling; exploratory analysis in notebooks; running and logging
model experiments; evaluating a model with accuracy/precision/recall; writing a data-loading
script; reading research or vendor documentation and summarising it; testing an API endpoint
of a deployed model; building basic dashboards.

**Tools:** Python, pandas, NumPy, Jupyter notebooks, scikit-learn, Git, SQL, spreadsheets.

**Illustrations:** data pipeline diagram, confusion matrix, learning/validation curve (only from
real experiments), dataset class-balance bar chart.

**Theory links:** linear algebra (matrix operations), probability and statistics, programming,
numerical methods.

---

## D. Electronics, repair and embedded/IoT
*(workshops, device repair, hardware start-ups)*

**Tasks:** component identification with a datasheet; continuity and voltage checks; soldering and
desoldering through-hole and SMD parts; hot-air rework; breadboard prototyping; programming a
microcontroller (Arduino/ESP32 class) to read a sensor or drive an output; enclosure and wiring
tidy-up; functional test sheets; fault logging.

**Tools:** multimeter, soldering station, hot-air station, oscilloscope (observing), bench power
supply, Arduino IDE or PlatformIO, logic probe.

**Illustrations:** circuit schematic, block diagram of the sensor-to-output chain, waveform sketch,
fault-finding flowchart.

**Theory links:** Ohm's law, Kirchhoff's laws, basic electronics (diodes, transistors), digital
logic and FSMs, physics of electricity.

---

## E. Telecoms and ISP
*(tower sites, fibre, wireless links, call centres' tech teams)*

**Tasks:** site safety induction; fibre and coax connector inspection; link testing; signal
strength readings; installing CPE (customer routers); handling customer fault tickets; reading
network monitoring dashboards as an observer; battery and generator checks at sites; documenting
site equipment.

**Tools:** optical power meter (observing), spectrum/signal apps, patch cords, monitoring
dashboard, ticket system.

**Illustrations:** point-to-point link diagram, signal level graph from real readings, site
layout sketch.

**Theory links:** wave physics, circuit basics, intro to communications, number systems and
binary arithmetic.

---

## F. Electrical, power and building services
*(facilities, estates, installation firms)*

**Tasks:** reading single-line diagrams; inspecting distribution boards; load and phase balance
checks with a clamp meter; generator and inverter changeover checks; earthing continuity checks;
cable sizing discussions; lighting and socket circuit installation under supervision;
maintenance logs.

**Tools:** clamp meter, multimeter, insulation tester (observing), cable tools, PPE.

**Illustrations:** single-line diagram, changeover circuit sketch, load profile graph from
real readings.

**Theory links:** basic electrical engineering, Kirchhoff's laws, circuit theory, physics of
electricity, engineering drawing.

---

## G. Cybersecurity and systems administration

**Tasks:** asset inventory and patch status checks; user access reviews; log reading and anomaly
flagging; reviewing firewall rules as an observer; phishing awareness material; backup
verification; Linux server basic configuration.

**Tools:** Linux shell, Windows admin tools, log viewers, vulnerability scanner reports
(read-only), spreadsheets.

**Illustrations:** network zone diagram, backup schedule timeline, access-control matrix.

**Theory links:** programming and scripting, number systems, Boolean logic, intro to computing,
authentication principles.

---

## H. Banking, fintech and POS operations
*(technology unit)*

**Tasks:** POS and ATM peripheral checks; branch connectivity checks; transaction sync queue
monitoring; helpdesk tickets from branches; end-of-day report checks; documenting procedures;
user provisioning under supervision; hardware replacement and functional testing.

**Tools:** ticket system, remote desktop, terminal diagnostics, receipt printer and scanner
configuration utilities.

**Illustrations:** branch-to-HQ data flow diagram, daily transaction sync timeline, escalation
flowchart.

**Theory links:** number systems, Boolean logic, programming, intro to databases, networking
basics.

---

## I. Manufacturing, industrial automation and maintenance

**Tasks:** machine inspection rounds; reading PLC ladder diagrams (observing); sensor and relay
checks; preventive maintenance schedules; safety lock-out/tag-out procedure observation;
downtime logging; panel wiring tidy-up.

**Tools:** multimeter, hand tools, HMI screens, maintenance schedule sheets, PPE.

**Illustrations:** ladder logic sketch, sensor-relay-motor block diagram, downtime bar chart
(only from real data).

**Theory links:** circuit theory, digital logic, physics, engineering drawing, control theory basics.

---

## J. Media, broadcast and creative technology

**Tasks:** studio equipment set-up; audio/video cabling and patching; encoder or streaming
checks; storage and backup of footage; software installation on editing machines; fault logging
on cameras and mixers.

**Tools:** audio/video cables and interfaces, streaming software, storage management tools.

**Illustrations:** signal-flow diagram, equipment rack layout.

**Theory links:** circuit basics, wave physics, number systems, digital encoding principles.

---

## K. Fallback — general technical intern

If the field is unclear or the student cannot specify, use a blend of A and B: shadowing the
technical team, helping with equipment set-up, fault logging, small scripts and documentation.
State the assumption clearly in the review sheet.

---

## Role modifiers

Apply these on top of any profile to adjust the verbs and autonomy level:

- **Intern / trainee**: heavy shadowing weeks 1–2, supervised tasks mid-placement, light
  ownership in final weeks.
- **IT support officer**: ticket-driven days, user-facing work, branch/site visits.
- **Developer intern**: sprint-driven days around a codebase, code reviews, PR submissions.
- **Technician's assistant**: field visits, hands-on tools, safety checks, testing.

Verb progression through the placement:
*observed* → *assisted* → *performed under supervision* → *carried out independently*
